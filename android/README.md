# Packing List — Android app

This wraps the [Packing List PWA](https://t3ste.github.io/packing-list/) as a real,
installable Android app using a **Trusted Web Activity (TWA)** — a full-screen Chrome
Custom Tab with no address bar, generated by Google's
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) tool. No app code lives
here; it's a thin native wrapper that loads the live website. Updating the website
updates the app automatically — no rebuild needed for content/feature changes, only
for things that touch the wrapper itself (icon, name, colors, permissions).

- **Package ID**: `com.t3ste.packinglist`
- **Digital Asset Links**: verified via `https://t3ste.github.io/.well-known/assetlinks.json`
  (hosted in the separate [`t3ste.github.io`](https://github.com/t3ste/t3ste.github.io)
  repo, since GitHub Pages project sites can't host files at the domain root).
  This is what lets the app open without a browser address bar — if it's ever
  misconfigured, the app still works, just shows the URL bar like a normal browser tab.

## Rebuilding

Requirements: JDK 17–21 (not newer — Gradle 8.x doesn't yet support JDK 22+), the
Android SDK (`build-tools`, `platform-tools`), and the [Bubblewrap CLI](https://github.com/GoogleChromeLabs/bubblewrap)
(`npm install -g @bubblewrap/cli`).

1. Get `android.keystore` (not in this repo — see **Signing key** below) into this folder.
2. `local.properties` needs one line: `sdk.dir=<path to your Android SDK>`.
3. Set the signing passwords as environment variables so you're not prompted:
   `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD`.
4. Run `bubblewrap build` in this folder. On first run it regenerates the project
   from `twa-manifest.json` (confirm "yes" when asked) and produces
   `app-release-signed.apk`.

If `bubblewrap build`'s own Gradle invocation fails to find `gradlew.bat`, run the
build steps directly instead:
```
./gradlew.bat assembleRelease
<Android SDK>/build-tools/<version>/zipalign.exe -v -p 4 app/build/outputs/apk/release/app-release-unsigned.apk app-release-unsigned-aligned.apk
<Android SDK>/build-tools/<version>/apksigner.bat sign --ks android.keystore --ks-pass pass:<password> --key-pass pass:<password> --ks-key-alias upload --out app-release-signed.apk app-release-unsigned-aligned.apk
```

To bump the app version for a new release, edit `appVersionCode`/`appVersion` in
`twa-manifest.json` before running `bubblewrap build`.

## Signing key

`android.keystore` is deliberately **not** committed (see `.gitignore`) — it's the
app's permanent signing identity. **Back it up somewhere safe.** If it's lost, no
future update can be signed to match what's already installed on users' devices;
everyone would need to uninstall and reinstall from scratch. The public half (the
SHA-256 certificate fingerprint) is already published in `twa-manifest.json`'s
`fingerprints` field and in the `assetlinks.json` above — that part is fine to share.

## Distribution

- **GitHub Releases**: the straightforward option — attach the signed APK to a
  [release](https://github.com/t3ste/packing-list/releases) on this repo.
- **F-Droid**: two paths, different effort —
  - Official F-Droid repo: requires the app be built from source by F-Droid's own
    servers, plus a review queue (weeks).
  - Self-hosted F-Droid repo: just a folder of APKs + a generated `index.xml`
    ([fdroidserver](https://f-droid.org/docs/Setup_an_F-Droid_App_Repo/) `fdroid
    update`), added to a client via a custom repo URL — same effort as a GitHub
    Release, no review process.

## Known limitations

- Requires Chrome (or another TWA-capable browser) installed on the device — a TWA
  is not a fully standalone renderer.
- `minSdkVersion` is 21 (Android 5.0+).
